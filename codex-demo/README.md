# 오전 실습 — 에이전트의 루프를 눈으로 보기

하루치 업무 로그에서 **요약 한 줄**을 만드는 작은 프로그램입니다.
지금은 깨져 있습니다. 고치는 건 여러분이 아니라 **Codex**입니다.

목표 출력:

```
2026-11-07 · 5건 · 총 170분 · 완료 3 · 실패 1 · 진행중 1
```

## 1. 빨간 걸 먼저 본다

```bat
cd codex-demo
python -X utf8 -m unittest discover -s tests -v
```

> [!IMPORTANT]
> **`-X utf8` 을 빼면 한글 테스트 이름이 깨져서 읽을 수 없습니다.**
> 윈도우 콘솔이 UTF-8이 아니라서 그렇습니다. 프로그램 잘못이 아닙니다.

일곱 개 중 **다섯이 빨갛습니다.**

| | 뜻 |
|---|---|
| **FAIL** 셋 | 돌긴 도는데 **값이 틀렸다** |
| **ERROR** 둘 | 아예 **터진다** |

둘은 다른 경험입니다. 그런데 **원인은 세 곳뿐입니다** — 한 곳을 고치면 빨간 게
두 개씩 사라지기도 합니다. 그걸 보는 게 오늘 오전의 핵심입니다.

## 2. Codex에게 맡긴다

```
테스트를 돌려서 실패하는 걸 전부 고쳐 줘.
명세는 tests/ 안에 있어. data/logs.csv 와 tests/ 는 고치지 말고
daily_report.py 만 고쳐.
```

**화면에서 볼 것** — 이게 "에이전트"입니다. 답을 한 번에 뱉는 게 아닙니다.

```
테스트 실행  →  빨간 걸 읽음  →  파일 수정  →  다시 실행  →  아직 빨감  →  또 수정  →  초록
    (관찰)        (판단)         (행동)        (관찰)        (판단)      (행동)
```

스스로 다음 할 일을 고르고, 결과를 보고 또 고릅니다. **이 루프가 에이전트입니다.**

## 3. 승인 모드를 바꿔 본다

같은 일을 승인 모드를 바꿔 다시 시켜 보세요. 체감이 다릅니다.

| 모드 | 무엇이 다른가 |
|---|---|
| `read-only` | 읽기만 합니다. 고치려 할 때마다 멈춰 묻습니다 |
| `workspace-write` | 이 폴더 안에서는 알아서 고칩니다 |

**이게 곧 "이 루프를 어디까지 믿을 것인가"입니다.** 남의 코드나 회사 저장소에서는
답이 달라집니다. 토큰을 얼마나 썼는지는 `/usage` 로 봅니다.

## 4. 오후와 어떻게 이어지나

오늘 오전에 한 일을 한 줄로 쓰면 **"매일 쌓이는 기록에서 요약 보고를 만든다"** 입니다.

오후에는 **똑같은 일을 노코드로** 합니다 — N8N으로 데이터를 가져와 요약해서
메일로 받습니다. 하루가 끝날 때 둘을 나란히 놓고 비교합니다.

| | 오전 (코드) | 오후 (노코드) |
|---|---|---|
| 도구 | Codex | N8N |
| 결과 | 항상 같은 값 | 돌릴 때마다 조금씩 다른 문장 |
| 고치는 법 | 테스트를 돌린다 | 실행 기록을 본다 |
